# SPEC-KIT — UI/UX Designer Standards

- 버전: 3.0
- 대상: HTML/CSS/Vanilla JS 기반 반응형 웹사이트
- 목적: AI 코딩 에이전트와 디자이너가 공유하는 재사용 가능한 디자인 규약
- 원칙: 프로젝트 요구사항과 실제 디자인 시안을 우선하며, 본 문서는 기본값이다.

## 1. 작업 순서
1. 기존 HTML/CSS, 이미지 자산, 디자인 참조, 콘텐츠 구조를 확인한다.
2. 기존 디자인 시스템과 클래스 규칙을 식별한다. 확정되지 않은 값은 가정으로 표시한다.
3. 시안별 공통 요소와 달라지는 요소를 비교해 레이아웃·타이포·간격·이미지·상태를 정의한다.
4. 구현에 필요한 토큰과 컴포넌트 규칙만 제안한다.
5. 320px부터 와이드 화면까지 시각적 회귀 및 접근성을 확인한다.

## 2. 디자인 토큰
- 원시(primitive) → 의미(semantic) → 컴포넌트(component) 계층을 권장한다. 작은 프로젝트는 원시+의미 두 계층도 허용한다.
- 색상, 간격, 폰트, 반경, 그림자, 모션은 반복되는 값부터 CSS Custom Properties로 관리한다.
- 원본의 한미 브랜드 블루/시안 값은 범용 표준이 아니라 프로젝트 예시다. 실제 브랜드 가이드가 있을 때만 채택한다.
- 단발성 예외값은 주석과 함께 허용하며, 모든 px 값을 토큰화할 필요는 없다.

```css
:root {
  --color-brand: #003876; /* 예시값: 프로젝트별 교체 */
  --color-text: #172b4d;
  --color-surface: #fff;
  --color-border: #c1c7d0;
  --color-focus: #0066cc;
  --space-1: .25rem;
  --space-2: .5rem;
  --space-3: .75rem;
  --space-4: 1rem;
  --space-6: 1.5rem;
  --space-8: 2rem;
  --container-max: 82.5rem;
  --font-sans: 'Pretendard', system-ui, sans-serif;
  --motion-fast: 150ms;
  --motion-normal: 250ms;
  --ease-standard: cubic-bezier(.4, 0, .2, 1);
}
```

## 3. 레이아웃과 반응형
- 기본 구현 방식은 Desktop First이며 `max-width` 미디어쿼리를 사용한다.
- 프로젝트에서 별도로 지정하지 않았다면 기본 브레이크포인트는 태블릿 1024px 이하, 모바일 390px 이하로 한다. 391~1024px 사이에서도 유동 레이아웃이 자연스럽게 동작해야 한다.
- 1025px 이상에서는 데스크탑 레이아웃을 유지하되, 고정 폭 요소는 `max-width`, `min()`, `clamp()`, `%`, `fr` 등으로 화면 밖으로 넘치지 않게 한다.
- 320px, 375px, 390px, 768px, 1024px, 1025px, 1440px에서 점검한다. 브레이크포인트는 콘텐츠가 깨지는 실제 지점에 따라 추가할 수 있다.
- 12컬럼 그리드는 선택 사항이며 모든 섹션에 강제하지 않는다.
- 이미지에는 적절한 `object-fit`, `aspect-ratio`, `max-width`를 사용하고 중요한 피사체의 크롭 위치를 명시한다.
- 모바일 내비게이션은 프로젝트 요구 시 햄버거 버튼과 우측 슬라이드 메뉴를 적용하며, 열림/닫힘 상태 및 포커스 흐름을 함께 설계한다.

## 4. 타이포그래피
- 본문 기본 크기는 일반적으로 16px 상당을 기준으로 하되 콘텐츠와 브랜드에 맞춰 조정한다.
- 제목에는 필요한 경우 `clamp()`를 적용하고 줄바꿈과 한글 행간을 시안별로 확인한다.
- 웹폰트에는 적절한 폴백과 `font-display` 전략을 적용한다.

## 5. 컴포넌트와 상태
- 인터랙티브 요소는 해당되는 상태만 정의한다: 기본, hover(지원 기기), focus-visible, active, disabled, loading, error, empty, success.
- 모든 컴포넌트에 모든 상태를 강제하지 않는다.
- `transition: all` 대신 전환할 속성을 명시한다.
- 카드 hover 효과는 키보드 포커스에서도 의미가 전달되어야 한다.
- 로딩 스켈레톤은 실제 비동기 로딩이 있을 때만 사용하며 축소 동작 설정을 따른다.
- 모달에는 배경, 닫기 버튼, 스크롤 가능한 내용 영역, 작은 화면에서의 크기 규칙을 정의한다.

## 6. 모션
- 이동·등장 효과는 가급적 `transform`과 `opacity`를 사용한다.
- `width`, `height` 등 레이아웃에 영향을 주는 애니메이션은 성능을 검토해 예외적으로 사용한다.
- 무한 반복 모션과 과도한 패럴랙스를 피한다.
- `prefers-reduced-motion: reduce`에서는 불필요한 이동·반복 애니메이션을 제거하거나 간단한 상태 전환으로 대체한다.
- `will-change`는 필요한 요소에 제한적으로 사용한다.

## 7. 접근성
- WCAG 2.2 AA를 목표로 한다. 일반 텍스트 대비 4.5:1, 큰 텍스트 3:1, 필수 UI 그래픽 및 경계 3:1을 확인한다(적용 예외 고려).
- 비활성 요소는 WCAG 텍스트 대비 규정의 예외가 있으므로 임의의 2.5:1 기준을 강제하지 않는다.
- 키보드 포커스는 눈에 띄게 표시하며 기본 outline을 제거할 때는 동등 이상의 대체 표시를 제공한다.
- 터치 대상은 가급적 44×44 CSS px 이상으로 설계한다. WCAG 2.2 AA의 최소 대상 크기 기준과 예외도 확인한다.
- 색상만으로 상태를 구분하지 않고 텍스트나 아이콘·설명을 병행한다.
- 의미 있는 이미지는 대체 텍스트를 제공하고 장식 이미지는 적절히 숨긴다.

## 8. 디자인 완료 기준
- [ ] 원본 시안과 주요 화면의 배치·간격·타이포·크롭이 일치한다.
- [ ] 320px 이상에서 의도하지 않은 가로 스크롤과 요소 겹침이 없다.
- [ ] 상호작용 상태와 모바일 메뉴·모달 디자인이 정의되었다.
- [ ] 색상 대비, 키보드 포커스, 축소 모션을 검토했다.
- [ ] 임의로 추가한 디자인 결정과 원본 시안과의 차이를 기록했다.
